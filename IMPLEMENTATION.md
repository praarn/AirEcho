# Implementation Reference

A deep walkthrough of how **Air Quality – Health Risk Correlator** is built: every
module, the data model, the two core pipelines, the modeling and RAG layers, the
frontend, and the infra. Read this alongside `README.md` (the *what* and *why*)
and `docs/DECISIONS.md` (the rationale + the honest list of simplifications).

---

## 1. System overview

Three genuinely irregular time series are aligned into one feature space:

| Series | Cadence | Source |
|--------|---------|--------|
| Pollutant readings (`pm25`, `pm10`, `no2`, `o3`) | per-station `nominal_cadence_minutes` (60 or 120), with real gaps | synthetic feed or OpenAQ v3 |
| Weather (temp, humidity, rainfall) | daily | synthetic (or OpenWeather key) |
| Self-logged symptom severity (0–10) + optional peak-flow | whenever the user logs | user via API/UI |

From those, the backend:

1. **Ingests** readings (raw, never "cleaned" on the way in), deduped on a natural key.
2. **Materializes** `exposure_windows` (6h / 24h / 72h) that each carry a `data_coverage_pct`.
3. **Builds lagged features** at t-0 / t-6h / t-24h / t-72h for each symptom log.
4. **Trains** a per-user `RandomForestRegressor` (with a linear baseline) once the
   user clears a minimum-data threshold; otherwise serves an anonymized
   **population fallback**; otherwise a labelled **heuristic**.
5. **Answers advisory questions** by retrieving WHO/CPCB guideline chunks from
   `pgvector` and letting an LLM *only rephrase* them, with inline citations and
   an explicit refusal path.
6. **Pushes live alerts** over WebSocket after each ingestion tick.

All background work is a single in-process `asyncio` loop — no Celery, no Redis.

## 5. Data model (`app/models.py`)

Schema is single-sourced from the ORM. Every table holding personal health data
carries a non-null `user_id` FK and is only ever reached through
`app/api/deps.py::scoped`.

### Auth & identity
- **`users`** — `id`, `email` (unique, indexed), `hashed_password` (bcrypt), `created_at`.
- **`refresh_tokens`** — `token_hash` (SHA-256 of the opaque token, unique), `revoked`,
  `expires_at`, `user_agent`, `rotated_to` (SHA-256 of the successor — a tamper trail).

### Sensor / environment
- **`stations`** — `source` (`openaq` | `cpcb` | `synthetic`), `external_id`,
  `location_name`, `lat`/`lng`, **`nominal_cadence_minutes`** (the denominator for
  coverage), `last_seen_at`. Unique on `(source, external_id)`.
- **`aqi_readings`** — `station_id`, `pollutant` (`pm25 pm10 no2 o3 so2 co`),
  `value`, `unit`, **`recorded_at`** (stored exactly as reported, never rounded),
  `ingested_at`. Unique on `(station_id, pollutant, recorded_at)` — the natural
  key used for idempotent upserts.
- **`weather_daily`** — `location`, `date`, `temp_c`, `rainfall_mm`,
  `humidity_pct`, `source_station`. Unique on `(location, date)`.

### User-scoped health data
- **`user_locations`** — `user_id`, `label`, `lat`/`lng`, `nearest_station_id`
  (SET NULL on station delete), **`distance_km`** (always stored — no silent
  "close enough"), `resolved_at`.
- **`symptom_logs`** — `user_id`, `severity` (0–10), `notes`, `peak_flow_value`,
  `peak_flow_photo_url`, `ocr_confidence`, **`manually_confirmed`** (a
  low-confidence OCR value is *not* trusted until this flips), `logged_at`
  (indexed — the alignment anchor).
- **`exposure_windows`** — `user_id`, `location_id`, `window_type`
  (`6h|24h|72h`), `window_start`/`window_end`, `avg_pm25/pm10/no2/o3`,
  `avg_temp`, `avg_humidity`, and the honesty triad
  **`data_coverage_pct` / `expected_slots` / `observed_slots`**, `computed_at`.
  Unique on `(user_id, location_id, window_type, window_end)`.
- **`risk_models`** — `user_id` (NULL ⇒ the shared population fallback),
  `model_type` (`personal | population_fallback`), `algorithm`
  (`linear_regression | random_forest`), `model_version`, `n_train`, `n_test`,
  `mae`, `baseline_mae` (predict-the-mean), `feature_importance_json`,
  `artifact_path` (joblib), `is_active`.
- **`risk_predictions`** — `user_id`, `model_id`, `risk_score`,
  `lag_features_json`, `explanation_json`, `predicted_at`.
- **`advisory_log`** — `user_id`, `question_or_context`,
  `retrieved_chunks_json`, `response_text`, `citations_json`, `refused`.

### RAG corpus
- **`guideline_documents`** — `title`, `source_url`, `publisher` (`WHO | CPCB`).
- **`guideline_chunks`** — `doc_id`, `chunk_text`, **`section_ref`** (e.g.
  `WHO AQG 2021 §Recommended levels — PM2.5` — what citations resolve to),
  `embedding` (`EmbeddingType(384)` — real `pgvector.Vector` on Postgres,
  JSON-encoded float list on SQLite).

### Observability
- **`ingestion_events`** — `station_id`, `source`, `status`
  (`ok | gap | failure | station_silent`), `detail`, `rows_ingested`. A station
  going silent is a *row here*, never a silent hole.
- **`audit_log`** — `actor_id`, `action` (`register | data_export | data_delete`),
  `target_table`, `target_id`.

## 6. Backend architecture

### 6.1 App startup (`app/main.py`)
`lifespan` creates `UPLOAD_DIR`, calls `scheduler.start(app)` (no-op if
`SCHEDULER_ENABLED=false`), and `await scheduler.stop()` on shutdown. CORS is
`allow_origins=["*"]` for dev. `/uploads` is a `StaticFiles` mount. Routers are
included from the 8 route modules. `GET /health` returns
`{status, scheduler_enabled, synthetic_ingest, last_ingest}` where `last_ingest`
is `scheduler.last_run()`. `GET /` is a pointer to `/docs` and `/health`.

### 6.2 Database wiring (`app/database.py`)
Sync `create_engine(..., pool_pre_ping=True, future=True)`; `SessionLocal` with
`autoflush=False, expire_on_commit=False`. `get_db()` is the FastAPI dependency
(yield + close). `EmbeddingType(TypeDecorator)` swaps implementation per dialect
so the whole suite runs on SQLite while production is always `pgvector`.

### 6.3 Auth & isolation
`app/core/security.py`:
- **Access token** — JWT `{sub, type:"access", iat, exp}`, HS256, 15-min TTL.
  `decode_access_token` rejects any token whose `type` != `access`.
- **Refresh token** — opaque `secrets.token_urlsafe(48)`; only its SHA-256 is
  stored. `rotate_refresh_token` on every `/auth/refresh`: verify → issue a fresh
  one → mark the presented row `revoked` and set `rotated_to`. **Reuse
  detection**: presenting an already-revoked token revokes *every* token for that
  user (`db.query(...).update({"revoked": True})`) and raises.
- `revoke_all_for_user` backs `/auth/logout` and `/privacy/delete`.

`app/api/deps.py`:
- `current_user` decodes the bearer token, loads the `User`, 401 on any failure.
- **`scoped(db, model, user_id)`** — the single choke point: returns
  `select(model).where(model.user_id == user_id)`. Handlers add `.where(...)` but
  can never widen past their own `user_id`.
- `get_owned_or_404` — fetch one row through `scoped`; **404 (not 403)** on miss
  so existence for another user isn't leaked.

- `/ws/admin-feed` — raw tick broadcasts.

### 6.5 WebSocket manager (`app/api/ws_manager.py`)
`ConnectionManager` holds `user_id → set[WebSocket]` and an admin set, guarded by
an `asyncio.Lock`, plus `_last_risk` for change detection. **The socket is a push
channel on top of a REST source of truth** — on reconnect the client re-fetches
via REST, the server never assumes the socket carried all state.

`evaluate_and_push_alerts()` runs after each ingestion tick, only for users with
a live socket:
- **Threshold alert** — latest `pm25` at the user's station `> WHO_PM25_24H`
  (15 µg/m³) ⇒ push `{type:"threshold_alert", value, who_guideline, station, …}`.
- **Risk update** — recompute `predict_for_user(..., persist=False)`; push
  `{type:"risk_update", …}` only when `|Δ| ≥ 0.5` since the last push.

## 7. Ingestion pipeline (`app/services/ingestion.py` + `scheduler.py`)

### Scheduler loop
`scheduler.start()` creates `asyncio.create_task(_loop())`. `_loop` sleeps 5s
(let migrations settle), then every `max(60, INGEST_INTERVAL_MINUTES*60)` seconds
runs `_tick()`. `_tick_sync()` (in the default threadpool, so the event loop and
WS broadcasts never block):

```
if SYNTHETIC_INGEST:  ingest_synthetic() ; ingest_weather_synthetic()
else:                  ingest_openaq()   (async, in _tick)
materialize_all()      # §8
retrain_everything()   # §10
```

`_tick()` then calls `evaluate_and_push_alerts()` and
`manager.broadcast_admin({type:"tick", …})`, and records `_last_run` (surfaced by
`/health`). Exceptions are caught so the loop stays alive; the error string lands
in `_last_run.error`.

### Design rules honored
- **Raw storage** — `recorded_at` is stored exactly as reported; no cleanup on ingest.
- **Idempotent upsert** on `(station_id, pollutant, recorded_at)` —
  `_upsert_reading` uses `ON CONFLICT DO UPDATE` on Postgres and a
  select-then-update on SQLite (dialect-aware so tests pass).
- **Silent stations** — `_flag_silent_stations` writes a `station_silent`
  `ingestion_event` for any station whose `last_seen_at` is older than 3h. Never
  a silent hole.
- **Synthetic feed** — `synthetic_readings_for_station` produces a two-hump
  diurnal PM curve + noise and *drops ~18% of slots entirely* (`gap_prob`) so the
  exposure pipeline is forced to be honest. Seeded RNG for reproducibility.
- **OpenAQ v3** — `ingest_openaq` is best-effort per station; on any
  `httpx.HTTPError` / parse error it writes a `failure` event and continues.

## 8. Exposure-window pipeline (`app/services/exposure_pipeline.py`) — CORE #1

### The coverage math
```
window_minutes    = (window_end - window_start) / 60s
expected_slots    = max(1, round(window_minutes / station.nominal_cadence_minutes))
observed_slots    = # distinct cadence-sized buckets in [start, end) that got ≥1 reading
data_coverage_pct = min(100, 100 * observed_slots / expected_slots)
```

The averages themselves are **plain means of the data that exists** — no
imputation, and the denominator is the observed count, *not* the expected count.
A window that only saw 40% of its expected readings is stored with
`data_coverage_pct = 40.0`, and that number rides along to the API, the model
(`coverage_lag*` features), and the dashboard `CoverageBadge`.

### `compute_exposure_window(...)` — the pure, unit-tested function
Signature: `(readings: DataFrame[pollutant, value, recorded_at], *, window_type,
window_start, window_end, cadence_minutes, weather=None) → WindowResult`.

1. Coerce window bounds to UTC; compute `expected_slots`.
2. Mask `readings` to `window_start ≤ recorded_at < window_end`.
3. `slot_idx = floor((recorded_at - window_start) / cadence)` clipped to
   `[0, expected_slots-1]`; `observed_slots = slot_idx.nunique()`.
4. `pollutant_means` = per-pollutant `groupby.mean()` over the in-window rows.
5. Weather: mean `temp_c` / `humidity_pct` over `[start-1d, end)` if a frame is
   passed (only for the t-0 sub-window in feature construction).
6. Return `WindowResult` (rounded), whose `as_row_kwargs()` maps to
   `ExposureWindow` columns.

### Materialization
- `materialize_for_location(db, loc, *, reference_time=None, window_types=None)` —
  anchor at `reference_time` (default now); fetch the widest readings frame once
  (`ref - 72h → ref`); for each window type compute + **upsert** on
  `(user_id, location_id, window_type, window_end)`. Fully reproducible from raw
  readings.
- `materialize_all(db, reference_time=None)` — loop over every `user_location`.
- `coverage_summary(windows)` → `{overall_coverage_pct, by_window_type,
  n_windows, worst_window}`.

Tests: `tests/test_exposure_windows.py` builds readings with deliberate holes and
asserts averages **and** coverage percentages against hand-computed values.

## 9. Lag-feature construction (`app/ml/features.py`) — CORE #2

### One feature row per symptom log
For a symptom logged at `t`, and each `lag ∈ LAG_HOURS = (0, 6, 24, 72)`:
- `anchor = t - lag`, sub-window `[anchor - 6h, anchor)` (`SUBWINDOW_HOURS = 6`).
- Reuse `compute_exposure_window` on that sub-window:
  - `{pol}_lag{lag}` = mean level of `pol ∈ (pm25, pm10, no2, o3)` (0.0 if none).
  - `coverage_lag{lag}` = that sub-window's `data_coverage_pct` — **a real
    feature**, letting the model discount a lag when the sensor was quiet.
- For `lag == 0` only: `temp`, `humidity` from the weather join.

`feature_names()` → `[pm25_lag0, pm10_lag0, no2_lag0, o3_lag0, coverage_lag0, …
(×4 lags), temp, humidity]` (22 features).

### Frames & split
- `build_training_frame(db, user_id)` — primary location = first with a resolved
  station. Fetch all symptom logs ordered by `logged_at`, fetch one wide readings
  frame spanning `first_log - 78h → last_log + 1h`, build a row per log. **Drop
  rows whose `coverage_lag0 < MIN_T0_COVERAGE_PCT` (1.0)** — no t-0 exposure
  signal to learn from. Columns: `feature_names() + severity + logged_at`.
- `aggregate_training_frame(db)` — concatenate every user's
  `build_training_frame` output, sort by `logged_at`. **`user_id` is never added
  to the frame**; an `assert "user_id" not in pooled.columns` guards it.
- `time_based_split(frame, test_fraction)` — sort by `logged_at`, cut at
  `(1 - fraction)`. **Never random.** Guarantees
  `max(train.logged_at) ≤ min(test.logged_at)`.

Tests: `tests/test_lag_features.py` checks the correct historical sub-window is
pulled per lag, plus insufficient-history and gap-straddling edge cases.

## 10. Risk modeling (`app/ml/{config,train,predict}.py`)

### Thresholds & their reasoning (`app/ml/config.py`)
| Constant | Value | Why |
|----------|-------|-----|
| `LAG_HOURS` | `(0, 6, 24, 72)` | predict near-term severity from *past* exposure, not same-day co-occurrence |
| `SUBWINDOW_HOURS` | `6` | each lag is a 6h average ending `lag` hours before the log |
| `MIN_T0_COVERAGE_PCT` | `1.0` | rows with zero t-0 coverage are dropped |
| `MIN_PERSONAL_SAMPLES` | `30` | with a 25% test split → ~7 test rows (smallest fold not dominated by 1–2 points) and enough for a shallow RF to see each lag×pollutant combo more than once |
| `MIN_PERSONAL_DAYS` | `14` | 30 logs from one week describe one pollution episode; two weeks can contain a high *and* a low regime |
| `MIN_POPULATION_SAMPLES` | `40` | minimum pooled rows before a population model is trained at all |
| `TEST_FRACTION` | `0.25` | chronological hold-out |
| `RF_PARAMS` | `n_estimators=200, max_depth=6, min_samples_leaf=3, random_state=42` | kept shallow on purpose — a deep forest memorizes tens-to-hundreds of noisy points |

Disclaimer strings (`DISCLAIMER_PERSONAL` / `_POPULATION` / `_HEURISTIC`) travel
with every prediction and are rendered verbatim in the UI.

### Training (`app/ml/train.py`)
`_fit_and_score(train, test)`:
1. `Pipeline([StandardScaler, LinearRegression])` — interpretable baseline; MAE
   on the future fold with predictions clipped to `[0, 10]`.
2. `RandomForestRegressor(**RF_PARAMS)` — primary; MAE on the same fold.
3. `baseline_mae` = predict-the-mean (`y_train.mean()`).
4. Return both models, both MAEs, RF `feature_importances_`, linear coefficients.

`_store_models(...)` writes **two `risk_models` rows per version** (linear —
`is_active=False`, kept for the metrics story; RF — `is_active=True`), after
`_deactivate_previous` flips older rows of the same `(user_id, model_type)`.
`_persist_artifact` joblib-dumps `{rf, linear, features}` to
`app/ml/artifacts/<tag>.joblib` (gitignored).

- `train_personal(db, user_id)` — gate on `n ≥ 30` **and** `span ≥ 14 days`;
  returns `TrainOutcome(trained=False, reason=...)` below either bar.
- `train_population(db)` — reads the anonymized pooled frame; gate on `n ≥ 40`.
- `retrain_everything(db)` — population first, then every user; called by the
  scheduler and the seed script.
- `write_metrics_doc(db)` — regenerates `docs/METRICS.md` from active models.

### Serving (`app/ml/predict.py`)
`predict_for_user(db, user_id, *, persist=True)`:
1. `_current_feature_row` — build the feature row anchored at *now* from the
   primary location's station.
2. `_active_model` selection order:
   1. active **personal** RandomForest,
   2. active **population_fallback** RandomForest,
   3. **heuristic** — `clip(2.0 + 4.0 * (pm25_now / 15), 0, 10)`, clearly
      labelled `model_type:"heuristic"`, `algorithm:"who_pm25_ratio"`, never
      presented as a model output.
3. Load the joblib artifact, predict, `clip(0, 10)`.
4. `_explain` — rank importances (or `abs(coef)` for the linear fallback), take
   top 6, attach each feature's `current_value` and a `_humanize` label
   ("PM2.5 exposure 24h before the symptom", "data coverage of the exposure
   window 6h before", …).
5. Response: `risk_score, model_type, algorithm, model_version, is_personalized,
   disclaimer, lag_features, explanation, data_coverage_pct, predicted_at`. If
   `persist`, insert a `risk_predictions` row.

Tests: `tests/test_risk_model.py` asserts the time-split property, the
personal/population gate, and the anonymization of the pooled frame.

## 11. Grounded RAG advisory (`app/rag/`)

### Corpus (`guidelines_data.py`)
`GUIDELINES` = a list of `{title, publisher, source_url, sections: [(section_ref,
text), …]}` — short faithful paraphrases of the WHO Global Air Quality Guidelines
2021 and CPCB National AQI so a fresh clone is demoable offline. Every numeric
threshold the advisory may state must trace back to one of these chunks.

### Embedding & indexing (`embed.py`)
`_model()` lazily loads `SentenceTransformer(EMBEDDING_MODEL)`, cached
process-wide (`lru_cache`). `embed_texts` encodes with
`normalize_embeddings=True`. `chunk_section` splits only sections longer than
~700 chars, keeping `section_ref` (with a `(part n)` suffix) so citations stay
precise. `index_guidelines(db, reset=True)` is idempotent: wipes + rebuilds
`guideline_documents` + `guideline_chunks` with embeddings. Unit tests
monkeypatch `embed_texts` — no weights downloaded.

### Retrieval (`retrieve.py`)
- **PostgreSQL**: `GuidelineChunk.embedding.cosine_distance(qvec)` ordered in the
  DB, `similarity = 1 - distance`. Backed by an IVFFlat index
  (`vector_cosine_ops`, `lists = 10`).
- **SQLite**: load all chunk vectors, normalize, dot-product in NumPy.
Both return `RetrievedChunk(chunk_id, section_ref, document_title, text,
similarity)`, highest first.

### Generation (`advisory.py`) — the hard rules
`generate_advisory(db, *, user_id, question, context)`:
1. `retrieve(db, query, top_k=RAG_TOP_K)`.
2. **Refusal**: if no chunks or `top_similarity < RAG_MIN_SCORE (0.32)` → log a
   `refused=True` `advisory_log` row and return `REFUSAL_TEXT` ("The available
   WHO and CPCB guidelines indexed here don't specifically address this …").
3. Otherwise build a context line ("current PM2.5 ≈ … µg/m³; population-fallback
   risk score …/10; exposure-window data coverage …%") and call the LLM with a
   system prompt that forbids stating any number/threshold/claim not in the
   passages and requires an inline `[n]` after every passage-derived sentence.
4. **`call_llm`** — OpenAI-compatible chat completion via `httpx`,
   `temperature=0.2`; returns `""` when unconfigured or on any error (never
   raises into the request path).
5. **Numeric guard**: if the LLM text has no `[n]` marker, or contains a numeric
   token (markers stripped) not present in any retrieved chunk or the context
   line → discard it and use `_template_answer` (deterministic renderer that only
   emits grounded, quoted, cited passages).
6. Citations: **every** retrieved chunk is surfaced (`marker, section_ref,
   document_title, score, snippet`) — the reader sees the full grounding, not
   just the markers the LLM chose. Log `refused=False`.

### Eval (`eval.py`)
`python -m app.rag.eval` (needs a migrated DB with guidelines indexed) reports
**citation-presence rate** over 5 grounded questions and **correct-refusal rate**
over 3 out-of-corpus questions.

Tests: `tests/test_rag.py` mocks both the embedder and the LLM and asserts
citation presence, correct refusal, and the untraceable-number → template
fallback.

## 12. OCR pipeline (`app/services/ocr.py`)

Deliberately just Tesseract digit-reading — an honest scoping choice, documented,
not a hidden limitation.

- `extract_peak_flow(image_bytes) → OcrOutcome{raw_text, extracted_value,
  confidence, needs_confirmation, engine}`.
- Pillow: grayscale + autocontrast. `pytesseract.image_to_data` with
  `--psm 7 -c tessedit_char_whitelist=0123456789`.
- `_digits_from_text` prefers 2–3 digit tokens inside the plausible range
  `(60, 900)` L/min.
- `confidence` = mean per-token Tesseract confidence, **capped at 0.4** if the
  value is out of range. `needs_confirmation` = value is `None` **or**
  `confidence < CONFIDENCE_THRESHOLD (0.75)` **or** out of range.
- Missing/broken Tesseract ⇒ `OcrOutcome("", None, 0.0, True, "unavailable")` —
  degrades, never crashes.
- `vision_llm_fallback` is a documented stub that *still* returns
  `needs_confirmation=True`.

A low-confidence value is stored but `manually_confirmed=False`, which keeps it
out of every model/chart until `POST /symptoms/{id}/confirm-peak-flow`.

Tests: `tests/test_ocr.py` renders digit images (skips cleanly if `tesseract`
isn't on PATH) and asserts the never-silently-trust property.

## 19. Deliberate simplifications

Full table in `docs/DECISIONS.md`. The headline ones:

- OCR is Tesseract digit-reading only; the vision-LLM fallback is a stub. Every
  low-confidence read is gated behind manual confirmation.
- `SYNTHETIC_INGEST=true` fabricates gappy readings when OpenAQ isn't reachable —
  the gap/coverage logic is identical for synthetic and real data.
- The guideline corpus is bundled paraphrases, not the full PDFs (swap in
  verbatim passages, keep the `section_ref`s).
- Weather is daily synthetic context, joined by station location name.
- One "primary" location per user drives the model.
- Population model = pooled rows with `user_id` stripped + time split; no
  k-anonymity / differential privacy beyond identifier removal.
- JWT in `localStorage` (portfolio SPA), but refresh tokens are hashed + rotated
  server-side with reuse detection.
- Single in-process `asyncio` scheduler, no leader election (fine for one
  backend replica; explicitly required by the brief).
